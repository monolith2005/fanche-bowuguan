# 翻车博物馆：完整功能缺口与接入清单

更新日期：2026-07-24

这份文档只记录从“当前可运行本地产品”走向“真实多人、真实 AI、真实抖音生态产品”仍缺少的内容。缺口不等于对应模块不存在：展馆、入馆、鉴定、处置、陪练、结果、内容生成、社区、馆长和商业服务在本地版都已有可操作入口与数据结构。

## 1. 真实案例库

### 当前缺少

- 当前只有眼线、小屋、奶油 3 件正式案例，家居、植物、拍摄馆没有真实馆藏。
- 每个案例的“同款结果”目前是同一案例下的三个知识切片，尚不是大规模跨用户检索结果。
- 缺少失败前目标图、过程视频、处理后结果图和用户确认结论。
- 原因概率是项目初期人工设定，尚未由标注集校准。

### 每个案例必须补齐的字段

```text
case_id
hall_id / 子类标签
授权用户或授权来源
原始图片或视频
目标图片或原教程关键帧
原教程作品 ID、作者 ID、时间点、链接权限
异常区域坐标或分割掩码
目标对象、当前阶段、异常形态、异常区域
严重程度、可逆程度、安全风险
材料、工具、操作历史、现实约束
原因候选、支持证据、排除证据
最终确认原因、确认方法、确认人
四类处置是否适用及原因
处理步骤、每一步验证条件
处理后图片或视频
用户是否完成、是否满意、是否愿意公开
案例审核状态、知识版本、模型版本
图片/视频授权范围和到期时间
```

### 建议的首批数量

| 展馆 | 最低可检索数量 | 建议比赛前数量 | 需要覆盖的关键子类 |
|---|---:|---:|---|
| 厨房事故馆 | 30 | 80—120 | 打发、烘焙、面团、煎糊、食品安全 |
| 变美事故馆 | 30 | 80—120 | 眼线、底妆、发型、美甲、染发 |
| 手作事故馆 | 30 | 80—120 | 结构、黏合、比例、编织、材料开裂 |
| 家居改造馆 | 15 | 50—80 | 贴膜、组装、墙面、收纳、清洁 |
| 植物急救馆 | 15 | 50—80 | 黄叶、徒长、积水、换盆、病虫 |
| 拍摄翻车馆 | 15 | 50—80 | 构图、光线、机位、运镜、模仿失败 |

最低数量只是让向量检索有候选，不能证明检索质量。所有案例都需要授权、审核和可追溯来源。

## 2. 视觉理解和失败指纹服务

### 需要的真实能力

1. 图片/视频预处理：方向校正、抽帧、去重、质量检测。
2. 目标对象识别：区分眼线、奶油、模型结构等实际对象。
3. 目标图与现场图对齐：计算差异，而不是只描述现场图。
4. 异常区域定位：矩形只是本地初始形态，最终需要关键点、分割或时序区域。
5. 结构化失败指纹生成：必须符合稳定 schema。
6. 不确定性输出：图片不足时返回需要补拍的视角，不能硬猜。
7. 高风险规则前置：食品、电器、刺激性材料不能只依赖通用大模型。

### 仍需提供或确定

- 当前多模态理解模型已选定为 `doubao-seed-2-0-lite-260428`（支持视频内音频理解）；Embedding 和重排模型仍需选择与开通。
- 每个模型的供应商、版本、价格、并发、限流和数据保留政策。
- 视频最大时长、图片最大尺寸、单次成本和目标响应时间。
- 是否允许将用户图片用于模型训练；默认建议不允许。
- 模型输出 schema 的版本管理方式。

### 必需 API

```text
POST /api/v1/media/upload
POST /api/v1/cases/analyze
POST /api/v1/cases/{id}/follow-up
POST /api/v1/cases/{id}/verify
GET  /api/v1/cases/{id}
```

`follow-up` 必须接收问题、用户答案或补拍媒体，返回更新后的原因概率、证据变化和下一条最有信息量的问题。

## 3. 同款失败视觉搜索

### 需要的索引

- 原始图片向量。
- 异常区域裁剪向量。
- 异常文本向量。
- 操作过程、材料、阶段的文本向量。
- 已确认原因、处理路线和结果的结构化索引。
- 视频问题片段的起止时间与关键帧向量。

### 三种排序不能混成一个假分数

| 排序 | 主要信号 | 必须返回的解释 |
|---|---|---|
| 长得最像 | 异常区域视觉向量、形状、纹理、颜色 | 哪个区域和视觉特征相似 |
| 经历最像 | 阶段、材料、工具、操作历史 | 哪些过程字段一致 |
| 最值得参考 | 已确认原因、处理完成、满意度、风险等级 | 为什么具有参考价值 |

### 需要确定

- 向量数据库产品与部署区域。
- Top-K 候选数、重排数、搜索延迟目标。
- 用户是否能要求删除向量及删除 SLA。
- 相似度阈值；低于阈值必须显示“未找到足够相似案例”。
- 视频片段与抖音原作品的授权播放方式。

## 4. AI 鉴定和垂类 Skill

### 每个展馆需要独立提供

- 可判断问题清单和不可判断问题清单。
- 原因假设树。
- 每个假设的支持证据、反证和最优追问。
- 抢救、改造、重开、止损的选择规则。
- 分步操作及每一步视觉验证条件。
- 必须人工介入的边界。
- 高风险禁答规则和紧急提示语。
- 内容审核人与审核周期。

### 需要的专家

- 厨房/食品安全审核。
- 眼部化妆与化妆品安全审核。
- 刀具、热熔胶、电器和家居安全审核。
- 植物养护知识审核。
- 摄影与视频制作知识审核。

专家身份、审核记录和知识版本不能用“AI 已验证”替代。

## 5. 分步陪练

### 当前缺少

- 眼线关键点与对称参考线模型。
- 结构模型的水平/垂直/角度测量。
- 奶油等动态状态的视频时序判断。
- “当前步骤是否完成”的可量化判定阈值。
- 用户主动退出、回滚和更换路线后的状态恢复。

### 后端数据结构

```text
rescue_run_id
case_id / user_id / selected_route
step_index / step_version
before_media / after_media
verification_result / confidence / evidence
manual_confirmation
risk_event
started_at / completed_at / abandoned_at
satisfaction_score
```

## 6. 馆藏档案和结果

### 需要后端实现

- 跨设备馆藏同步。
- 原图、目标图、过程图、结果图的对象存储。
- 用户编辑展品名、隐私范围和公开状态。
- 完整复盘报告导出。
- 删除、撤回公开和数据导出。
- 同类馆藏数量必须实时来自数据库，不能写死。
- “抢救成功”只能来自用户确认或明确验证规则，不能因走完步骤自动成立。

### 当前已经有

- 三种真实生成的脚本/分镜。
- 可下载 PNG 馆藏分享卡。

### 仍缺少

- 目标图、现场图、过程复拍和结果图的时间线编辑器。
- 视频渲染服务：字幕、转场、画幅、封面、配音、音乐。
- TTS 声音选择与授权。
- 字体、音乐、贴纸和视频模板的商用授权。
- 内容安全审核。
- 抖音发布权限、草稿箱能力和发布结果回调。
- 用户在发布前逐项确认素材和文案的界面。

### 建议 API

- 抢救结果可以发布到社区。
- 镇馆之宝不会预置虚假排行。

- 机器审核与人工审核后台。

- 联盟成员、订阅、通知和退出机制。
- 馆长会诊的邀请、认领、结论采纳和争议处理。

## 9. 馆长与创作者体系

### 当前本地模块具备

- 馆长、鉴定员、修复师、品牌 Skill 维护者申请。
- 专业经历填写和“待审核”状态。
- 典型案例、15 秒抢救胶囊、处理边界、品牌 Skill 草稿提交。

### 真实体系仍缺少

- 专业资质、作品经历和主体审核。
- 展馆角色、权限、有效期和撤销机制。

## 10. 商业化与本地服务

### 工具与材料数据

- 真实商品 ID、名称、规格、适用原因、禁用条件。
- 价格、库存、配送范围和更新时间。
- 是否广告、合作或联盟商品。
- 推荐必须能解释“诊断中的哪条证据触发了它”。

### 课程数据

- 课程/教程 ID、创作者、覆盖技能、适合阶段。
- 与失败指纹的匹配规则。
- 原作品跳转方式和转化回传。

### 本地服务数据

- 服务商主体、资质、城市、服务范围、价格区间、营业时间。
- 可处理/不可处理问题。
- 预约、取消、退款、投诉和评价。
- 定位权限及距离计算。

当前产品只保存服务需求，不会展示虚构商家、价格、销量或距离。

## 11. 抖音生态接入

需要向赛事或开放平台确认以下能力是否开放，以及所需 Scope、审核材料和降级方案：

- 教程视频长按 → 圈选目标 → “我翻车了”。
- 携带原视频 ID、作者、当前播放时间和选区进入小程序。
- 从评论区、搜索结果或视频挂载进入指定鉴定上下文。
- 跳回原教程指定时间点。
- 获取创作者公开作品和授权评论区问题。
- 发布生成视频或写入草稿箱。
- 话题挑战、商品、本地服务和小程序之间的跳转。

在权限没有书面确认前，不能把这些能力视为已经可用。

## 13. 隐私、合规与安全

必须由实际主体提供并经法律审核：

- 隐私政策、用户协议、社区规范。
- 人脸、眼部、声音、定位等敏感信息的单独同意。
- 图片上传目的、处理方、存储区域、保存期限和删除方式。
- 第三方模型供应商清单。
- 用户内容公开授权和二次用于生成内容的授权。
- 原教程、创作者内容、字体、音乐和图片版权。
- 食品、化妆品、电器、医疗相似场景的免责声明不能替代安全规则。
- 用户数据导出、删除、撤回授权和账号注销流程。

## 15. 素材清单

### 品牌素材

- 正式 Logo、图标、应用名称英文规范。
- 主题色、字体授权、深色/浅色规范。
- 启动页、默认头像、空状态、错误状态。

### 展馆素材

- 六展馆封面图或插画。
- 每个展馆的图标和分享封面。
- 社区五个分区的视觉标识。
- 馆长徽章、鉴定员徽章、审核状态图标。

### 内容模板素材

- 纪录片、展品解说、翻车法庭的片头、片尾、字幕、转场。
- 授权音乐、音效、字体和贴纸。

当前 Web 版使用 CSS 完成主要视觉，不依赖这些素材也可运行；正式参赛和发布仍应补齐品牌资产。

## 16. 测试集与验收标准

### AI 与检索

- 每个深度案例类别至少 50 个有人工相关性标注的查询。
- Top-5 视觉召回率、过程召回率和已验证案例命中率。
- 错误展馆率、无结果正确拒绝率。
- 原因 Top-1/Top-3 命中率及概率校准误差。
- 关键追问后信息增益。
- 高风险建议拦截率，目标应接近 100%。

### 产品

- 桌面、移动浏览器和后续抖音真机测试。
- 弱网、上传中断、超大图片、长视频、权限拒绝。
- 本地/云端记录恢复、重复提交、删除和注销。
- 社区审核、举报、馆长内容下架。
- 视频生成失败和发布失败后的可恢复性。

## 17. 当前决策仍需要产品方明确

1. 首发是否只开放三个深度展馆，其他三馆允许投稿但不开放 AI 处置，还是六馆全部开放有限能力。
2. 用户图片默认仅诊断，还是默认也进入私有馆藏；公开必须单独确认。
3. 馆长是平台认证身份、创作者荣誉体系，还是可付费服务者。
4. “抢救成功”的最终确认权由用户、视觉规则、馆长还是三者共同决定。
5. 食品安全等高风险类别是否允许生成任何继续加工步骤。
6. 社区是否允许匿名发布，以及人脸图片是否默认打码。
7. 商业推荐的收入模式：广告、佣金、本地服务抽成、品牌 Skill 还是组合。
8. 比赛现场使用真实云端 API，还是本地部署的可控服务。

这些决策会改变权限、合规、数据结构和研发优先级，应在接入真实后端前确认。

## 18. 推荐实施顺序

### P0：比赛可验证闭环

1. 为三类深度案例补真实同款数据和人工标注。
2. 接通分析、检索、追问更新和复拍验证 API。
3. 建立安全规则和专家审核。
4. 云端保存馆藏、社区帖子和馆长内容。
5. 生成真实视频成片，至少支持一种模板。

### P1：完整社区与创作者供给

1. 账号、公开授权、评论、会诊、联盟、审核。
2. 馆长认证、内容版本和召回统计。
3. 抖音原教程回流和创作者数据归因。

### P2：商业化

1. 真实商品/课程/服务商目录。
2. 诊断证据驱动的推荐规则。
3. 交易、预约、退款、广告标识和转化归因。
