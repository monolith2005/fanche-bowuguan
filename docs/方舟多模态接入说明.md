# 火山方舟多模态接入说明

## 当前接入状态

- 服务商：火山方舟。
- API：Responses API，`https://ark.cn-beijing.volces.com/api/v3/responses`。
- 模型：`doubao-seed-2-0-lite-260428`。该版本在方舟模型元数据中明确支持 `text / image / video / audio` 输入；`260215` 不声明音频输入，不能用于依赖视频口播的案例。
- 已验证：API Key 鉴权、真实图片理解、真实视频理解、结构化失败鉴定、关键追问后的概率更新。
- 密钥位置：只存在于本地服务进程环境变量 `ARK_API_KEY`，不会写入浏览器、Git、JS、文档或日志。

## 启动

双击项目根目录的 `start-local.bat`，或运行：

```powershell
.\start-local.ps1
```

首次启动时，脚本会提示输入 API Key：

- 输入不在终端显示；
- 明文只进入当前服务进程；
- 使用 Windows DPAPI 加密后保存在 `%LOCALAPPDATA%\FailureMuseum\secrets`；
- 只有当前 Windows 账户能够解密；
- 后续启动会自动加载，不再重复询问；
- 不会写入项目、Git、浏览器或前端代码。

如需清除并重新输入：

```powershell
.\start-local.ps1 -ResetKeys
```

服务启动后访问：

```text
http://127.0.0.1:5173/web/
```

健康检查：

```text
GET http://127.0.0.1:5173/api/v1/health
```

## 真实分析接口

```text
POST /api/v1/cases/analyze
Content-Type: multipart/form-data
```

字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| image | File | 图片或视频现场，沿用前端现有字段名 |
| target_image | File | 可选目标效果图 |
| description | String | 用户过程描述 |
| target | String | 目标结果 |
| constraints | String | 时间、预算、材料和处理限制 |
| source_url | String | 原教程链接或标识 |
| source_time | String | 异常发生时间点 |
| region | JSON String | 用户框选的归一化异常区域 |

图片会作为 `input_image` 输入，视频会作为 `input_video` 输入。媒体在本地代理中转成 Data URL 后发送给方舟，不会经过第三方图床。

## 返回内容

返回结果经过服务端 JSON 解析和 schema 归一化，包含：

- 是否检测到真实失败状态和判断置信度；
- 展馆、展品名、目标、阶段；
- 异常形态和异常区域；
- 严重度、可修复性、可逆性；
- 可核验视觉/视频证据；
- 原因假设、概率和仍需确认的证据；
- 一条关键追问；
- 安全提示；
- 抢救、改造、重开、止损四条路线；
- 实际模型 ID 和真实模型输出标记。

如果模型偶发返回少逗号、错误布尔值等非标准 JSON，服务端会把原始文本交给模型做一次“只修语法、不增加事实”的纠正，然后再次执行 schema 校验；用户媒体不会因此重复上传。

当前没有向量案例库，因此 `matches` 固定为空数组，模型提示词明确禁止编造同款案例和馆藏数量。

## 关键追问更新

```text
POST /api/v1/cases/{case_id}/follow-up
Content-Type: application/json
```

请求：

```json
{
  "question": "当前关键追问",
  "answer": "用户回答"
}
```

服务会把原分析和新证据重新交给模型，返回更新后的完整原因概率、追问、安全提示和处置路线。

分析上下文目前保存在 Python 进程内存中。重启服务后需要重新上传；正式后端应改为数据库或有过期时间的缓存。

## 复拍验证

```text
POST /api/v1/cases/{case_id}/verify
Content-Type: multipart/form-data
```

字段：`image`、`step`。模型只判断当前步骤是否有足够视觉证据完成，不允许把步骤完成夸大成最终抢救成功。

## 可信度保护

模型必须先输出：

```json
{
  "failureDetected": true,
  "analysisConfidence": 0
}
```

当 `failureDetected=false` 时，服务端强制：

- 异常改为“未观察到明确失败状态”；
- 原因改为“当前媒体不足以确认失败原因”；
- 禁止给出实质修复步骤；
- 要求补充目标图、异常时间点或更清晰媒体。

这是为了避免模型把普通图片或视频强行解释成“翻车”。

本地回归已分别验证：眼线异常图片会生成真实失败指纹和三条原因假设；正常花朵视频会返回 `failureDetected=false`，且只推荐暂停并补充证据。

## 限制

- 默认最大上传 50MB，可通过 `MUSEUM_MAX_UPLOAD_MB` 调整。
- 视频使用 `fps=1.0` 抽帧参数；长视频的成本和延迟会显著增加。
- API 调用会产生方舟费用。
- 当前服务仅监听 `127.0.0.1`，手机局域网访问需要额外改为 `0.0.0.0` 并配置防火墙。
- 当前没有真实同款向量检索、云端案例存储和用户账号。
- 模型结论属于假设，不替代食品安全、医疗、电器等专业判断。
